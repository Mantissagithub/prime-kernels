# Experiment 228: B1 phase profile and scheduling trials

Diagnostic result, no adoption or new speedup. Root implemented and ran the work directly; production kernel source is unchanged from 996d8d4.

Two valid profile processes compare a private instrumented clone with the actual package. All six exact hidden/KV cases and captured poisoned fallback/GU-refresh checks pass. No register spills: B1 remains 253 registers; B2 rises 246 to 254. B1/context 128 second-process median CTA sums across 32 layers are 196,721.75 / 148,384.25 / 2,911,826.25 / 1,202,563.5 cycles for metadata-first-hints/grid wait, norm2, thread0 GU loop, down-hints/grid wait. These are scheduled thread0 intervals, not pure DRAM costs, maximum across all warps, or additive wall shares. Instrumentation changes B1 latency by −1.22% to −1.51% and B2 by +0.70% to +0.89%; its faster B1 timing is not adopted as a performance improvement.

The uninstrumented one-line warp-major B1 mapping balances GU rows per CTA from 112/104 to 107/106. Exact parity/refresh/fallback pass, but B1 medians −0.356/−0.283/−0.139% at 32/128/1024 pass only 2/3, 2/3, 1/3 strict blocks. One process, no verified gain, not adopted. B2 is not changed intentionally. The separate B1-only compiler-fence source emits byte-identical B1/B2 kernel instruction words, including control bits, to the package; no pointless GPU timing was run for it. Both trials retain the original math and reductions.
