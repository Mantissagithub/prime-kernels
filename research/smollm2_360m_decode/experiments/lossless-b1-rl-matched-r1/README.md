# Experiment 235: matched-work full RL and startup overlap

Five complete processes per arm compare the CURRENT accepted B1 kernel with serial versus early trainer startup. Both use one real full-parameter SmolLM2-360M alphabet-sort update, FP32 optimization/reduction, stream64 filesystem weight updates, one inference sequence and fixed two-episode concurrency. Checkpoint saving is disabled in both arms. Early startup overlaps trainer imports with inference startup; trainer CUDA initialization retains the existing inference-readiness wait.

The private seed hook assigns distinct deterministic seeds per prompt/session, keeping temperature 1 and group variation. It does not replay outputs or change rewards, task data, training math or no-signal filtering. All ten runs issue the exact same multiset of 128 successful requests, with identical prompt hashes, seeds, output-token hashes and token counts, no failed/cancelled requests. All have identical finalized training work (118 rollouts, 114 no-signal discards) and identical recorded loss/gradient metrics. The total request stream includes rollout work beyond finalized trainer metrics; finalized counts are not the complete GPU workload.

Serial-start times (seconds): 53.560394, 53.749305, 59.870677, 51.104758, 51.327908. Early-start times: 52.315788, 50.581989, 46.712818, 44.269493, 43.567962. Read summary.json for full precision; this prose is rounded. Medians 53.560 to 46.713 s, 12.785% lower. Both A-B-B-A blocks pass the both-beat-both gate; the final control/early pair also passes. Block mean changes are -4.111%, -18.016% and -15.118%. The whole-arm timing ranges overlap: controls 51.105–59.871, early 43.568–52.316. The direction repeats within blocks, but effect size is noisy and should not be presented as a universal 12.8% gain.

This is a matched-work, ONE-UPDATE B1-only RL result. It does not measure the default two-sequence preset, longer training, checkpoint saving, or a kernel-only speedup. The opt-in profile exposes the measured startup/batching settings; it does not change the default preset. The historical 135M wall-time points are separate workloads.

An initial diagnostic pair (`a1`, `b1`) compared pre-Experiment-233 versus current B1 kernels with serial startup: 59.903 versus 53.560 s. It is one pair, with a gap much larger than the small decoder gain can explain; no isolated kernel-only RL speedup is established. `b1` then serves as the first current-kernel serial-start control in the startup experiment. Do not use old-kernel `a1` in the five-per-arm startup medians.

All guards pass with zero job swap; exact guard metrics are in summary.json and per-run records. The attempted V1 GPUModelRunner counter hook remains zero under the actual V2 runner; those counters are invalid and are NOT used as workload evidence. Work matching uses complete successful inference-request hashes/counts plus native training metrics, and the active batch-one lossless route/library SHA is verified. Kernel-library overrides choose real compiled kernels before runtime creation. Absolute paths in scripts refer to the original local fixtures/libraries; this is an evidence archive, not a standalone benchmark release. Compiled libraries, model weights and broadcasts are excluded.
