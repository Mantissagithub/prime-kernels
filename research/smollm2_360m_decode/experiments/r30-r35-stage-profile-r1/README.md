# R30 and R35 R2 stage profile

This probe asks whether R35's isolated packed QKV/O projection behavior survives in full decoder phases. It profiles R30 and R35 R2 independently against their own uninstrumented libraries. The baseline source remains the frozen candidate source. Instrumentation is added only to private copies in this directory.

Each run uses one baseline/profile pair. It requires bitwise equality of final hidden state and every layer's K/V cache between the pair before emitting measurements. CUDA-event ABBA samples compare uninstrumented and instrumented call duration. The analyzer emits profiler overhead for each case and a pass gate at or below five percent. These numbers quantify profiler perturbation only.

Both variants use the same 11 clock64 slots and semantic phase boundaries: norm1; QKV projection plus candidate O-row prefetch and its existing grid barrier; RoPE/current KV append and the cache visibility barrier; split-KV and its existing publish barrier; merge; O projection/residual plus candidate gate/up prefetch and its barrier; norm2; gate/up/SwiGLU plus candidate down prefetch and its barrier; activation staging/down projection/residual plus candidate next-layer QKV prefetch and its barrier; optional layer capture; and final norm. The source generator anchors each insertion to a unique multi-line context. It fails if an anchor is absent or ambiguous. CPU preflight separately checks that R35's packed/float norm and QKV `if constexpr`/`else` branches remain adjacent, that no clock read falls inside a debug-only block, and that profile markers follow the intended phase order. It also strips the generated instrumentation diff with a strict reverse patch and requires exact baseline recovery.

The analyzer keeps each CTA's work and existing-grid-barrier wait separate, sums serial intervals only within a CTA, and does not subtract timestamps across SMs. Work includes local stalls and barriers. Grid wait includes arrival skew. Phase fractions are descriptive. The maximum same-CTA named-cycle sum divided by a separate CUDA-event duration is an effective coverage estimate, not a calibrated SM frequency.

`invalid-prep-r1/` preserves the rejected zero-context patch attempt and its manifests for audit. Do not build or run those files. The active `r30-profile/` and `r35-profile/` directories are generated by the semantically anchored `prepare_sources.py`.

## Run sequence

1. Run `UV_CACHE_DIR=/tmp/tiny-prl-profile-uv uv run --offline --no-project --python /home/pradheep/.venv/bin/python python prime-rl/outputs/megakernel-20261025/r30-r35-stage-profile-r1/prepare_sources.py` for CPU-only source preparation and semantic/ABI validation.
2. Have the root reviewer inspect the generated diffs before any build. Then build each profile DSO separately with `build_profile.sh r30` and `build_profile.sh r35` under the existing GPU/build guard.
3. Run `profile_bench.py --pair r30` or `--pair r35` through the root-owned sequential guarded harness. Begin with `--cases seed17-b2-ctx32,seed17-b2-ctx128`, then run the B1 placebo cases.
4. Analyze each pair separately with `analyze_stage_profile.py results/<pair>.json --output results/<pair>-summary.json`.

No build, model load, GPU call, production edit, or environment change was performed during source preparation.
