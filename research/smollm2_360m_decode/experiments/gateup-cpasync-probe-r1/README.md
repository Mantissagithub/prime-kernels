# Gate/up cp.async microprobe

This isolated source probe compares the R30 paired gate/up weight path with a PTX `cp.async` double-buffered weight path. It is restricted to B2 and the actual cached SmolLM2-360M gate/up matrices: 32 layers, each with concatenated `[5120,960]` BF16 weights (gate `[2560,960]`, then up `[2560,960]`). Total GPU gate/up weights are 314,572,800 bytes. The harness reads only those tensors from the existing safetensors file; it never materializes or synthesizes model weights. Activations are seeded synthetic BF16 values, expanded to FP32 in shared memory.

Both arms use 24 CTAs, 256 threads, 8 warps per CTA, and the R30 B2 mapping `gw = warp * 24 + CTA`, advancing by 192 rows. Both preserve paired G/U rows, four FP32 accumulators per output, the same BF16-to-FP32 conversion, FMA operand order, reduction order, and `[B, G-then-U]` output layout. Both run R30's 128-byte-per-lane `prefetch.global.L2` over their owned gate and up rows. Baseline weight loads are R30 `__ldg(uint4)` loads. The async arm uses `.cg` 16-byte `cp.async` copies into two shared buffers, one per output row (G and U), lane, and warp.

The static async tile uses `2 buffers * 8 warps * 2 rows * 32 lanes * 16 bytes = 16 KiB`. FP32 activations add `2 * 960 * 4 = 7,680` bytes, for 24,064 bytes total static shared memory, below 24 KiB by 512 bytes. Each lane copies one 16-byte chunk per row. K=960 gives 120 chunks: at iteration 3, lanes 24 through 31 issue `src_size=0` with an in-bounds fallback global pointer, so the partial final group zero-fills without an out-of-bounds address. A warp commits the initial group, issues the next iteration while the current group is pending, waits with `wait_group 1` when a newer group remains, and uses `wait_group 0` on the final iteration before reading/reusing the buffer. Each warp handles its rows uniformly; there are no CTA barriers inside the row loop. After completion the consumer executes `__syncwarp()` and a compiler memory clobber before shared reads.

The harness captures one graph per arm. It resolves the current CUDA stream inside each enqueue callback. It poisons outputs after capture, replays both graphs, and requires every output element to be finite and FP32/BF16-bit exact before collecting timing. Ten alternating placements give five placements per arm, with five raw CUDA-event samples per placement. Reports include checkpoint/source/harness/library hashes, work counts, raw samples, and ptxas output when requested. Graph replay write verification prevents an empty graph from being timed. CUDA launch/API failures raise nonzero errors.

This is a standalone projection microprobe. Its full-row L2 prefetch and repeated execution over cached weights do not reproduce the complete decoder's producer/consumer overlap, launch context, or cache competition. A measured result would describe only this harness; it must not be presented as a full-kernel speedup.

## Commands

`python harness.py --build-only` compiles without importing torch, loading weights, or using a GPU. Add `--ptxas-verbose` to print and retain ptxas register, spill, and shared-memory diagnostics in `ptxas.log`. Existing outputs are protected; use `--force` to replace a prior library or `results.json`. `python harness.py --skip-build` uses an existing library and runs the GPU comparison. `python build_argv_preflight.py` checks the exact compiler argv with a stub and never invokes nvcc.

Source references used for PTX semantics: NVIDIA [PTX ISA, Asynchronous Copy](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-cp-async) and CUTLASS [SM80 async copy helpers](https://github.com/NVIDIA/cutlass/blob/main/include/cutlass/arch/memory_sm80.h). No CUTLASS dependency is introduced.
